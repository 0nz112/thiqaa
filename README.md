# منصة ثقة — بوت تيليغرام + Mini App

بوت تيليغرام مع تطبيق مصغّر (Mini App) لإدارة المحفظة، تنفيذ المهام المدفوعة، والاستثمار في مشاريع معلنة،
مع لوحة قرارات للمشرفين داخل تيليغرام.

## المكوّنات
| الملف | الوظيفة |
|---|---|
| `src/bot.js` | البوت: رسالة الترحيب، مشاركة رابط الإحالة، توثيق الهاتف، أزرار قبول/رفض للمشرفين، أوامر الإدارة |
| `src/server.js` | واجهة API للـ Mini App مع التحقق من توقيع تيليغرام في كل طلب |
| `src/finance.js` | كل العمليات المالية (إيداع، سحب، استثمار، تسوية، مكافآت) داخل معاملات قاعدة بيانات |
| `src/security.js` | تشفير AES-256-GCM للبيانات الحساسة، التحقق من initData، التحقق من الهاتف والبطاقة |
| `src/db.js` | قاعدة SQLite + سجل تدقيق غير قابل للحذف أو التعديل |
| `public/index.html` | واجهة الـ Mini App (أخضر وكحلي داكن، RTL) |

## التشغيل السريع (3 خطوات)
1. ثبّت **Node.js** (نسخة LTS) من nodejs.org.
2. ضع توكن البوت في ملف `.env` في سطر `BOT_TOKEN=`.
3. شغّل `start-windows.bat` (أو `start-mac-linux.sh`).

ستظهر في النافذة رسالة فيها رابط البوت وأمر مثل `/admin 123456` — أرسله للبوت لتصبح المشرف.
رابط المنصة (HTTPS) ومفتاح التشفير واسم البوت تُضبط تلقائياً. اترك النافذة مفتوحة ما دمت تريد البوت يعمل.

للتشغيل الدائم على خادم: ضع رابطاً ثابتاً في `WEBAPP_URL`، وشغّل بـ `pm2 start src/index.js --name thiqa`.
ملف `.gitignore` يمنع رفع `.env` ومجلد `data/` إلى GitHub.

## النشر على Railway من GitHub
1. ارفع المشروع إلى مستودع **خاص** على GitHub (بدون ملف `.env`).
2. في Railway: New Project ← Deploy from GitHub repo ← اختر المستودع.
3. Variables: أضف `BOT_TOKEN`.
4. Settings ← Networking ← **Generate Domain** (يُستخدم تلقائياً كرابط المنصة).
5. أضف **Volume** على المسار `/app/data` (قاعدة البيانات ومفتاح التشفير).
6. من Deploy Logs انسخ أمر `/admin ……` وأرسله للبوت.

## كيف تعمل مشاركة الإحالة
عند `/start` تظهر رسالة فيها زر **«مشاركة رابط الإحالة مع جهات اتصالك»**. عند الضغط يفتح تيليغرام قائمة المحادثات،
ويختار المستخدم من يريد إرسال الدعوة إليه، فتُرسل رسالة تعريفية مع رابطه الشخصي وزر «انضم إلى المنصة».
يُسجَّل المُحيل تلقائياً عند تسجيل الشخص الجديد، ويصله إشعار.

> تيليغرام لا يسمح للبوتات بالوصول إلى جهات اتصال المستخدم أو مراسلتها تلقائياً؛ الإرسال يتم دائماً باختيار المستخدم.
> الإرسال الجماعي التلقائي يُصنَّف سبام ويؤدي إلى حظر البوت والحسابات.

## محافظ الاستلام
من المحفظة ← «إضافة»:
- **زين كاش**: اسم صاحب الحساب، رقم الهاتف، العنوان.
- **كي كارد (ماستركارد)**: اسم صاحب البطاقة، رقم البطاقة (يُتحقق منه بخوارزمية Luhn)، رقم الهاتف، العنوان.

الهاتف والعنوان ورقم البطاقة مشفّرة في قاعدة البيانات، ويظهر للمستخدم الرقم مقنّعاً فقط (•••• 1234).
لا يطلب النظام أبداً PIN أو CVV أو تاريخ الانتهاء. تظهر البيانات الكاملة للمشرفين فقط داخل طلب السحب ليتمكنوا من التحويل.

## دورة العمليات
- **الإيداع**: المستخدم يحوّل ويرفع الإثبات ← تصل الصورة لمجموعة المشرفين بأزرار قبول/رفض ← يُضاف الرصيد ويُبلَّغ المستخدم.
- **السحب**: يُحجز المبلغ (معلّق) ← المشرف يحوّل يدوياً ثم يضغط «تم التحويل» ← أو «رفض» فيعود المبلغ للرصيد.
  مع حد أدنى، حد يومي، رسوم معلنة، وشرط توثيق الهاتف.
- **المهام**: لا تتطلب أي إيداع. التسليم يصل للمشرفين ← القبول يضيف المكافأة كـ«مكافأة مهمة».
- **الاستثمار**: يتطلب توثيق الهوية (المستوى 2). عند نهاية المشروع يسوّيه المشرف بالنسبة الفعلية المدققة.

## صفحة سحوبات الأعضاء
تعرض السحوبات التي نفّذها المشرفون فعلاً فقط (من جدول `withdraw_requests` بحالة approved): الاسم الأول + أول حرف من اسم العائلة،
المبلغ الصافي، طريقة الاستلام، ووقت التنفيذ، مع إحصائيات (العدد، آخر 30 يوماً، الإجمالي).
يظهر إشعار داخل التطبيق عند تنفيذ سحب جديد (فحص كل 30 ثانية). يستطيع كل مستخدم إخفاء اسمه من «حسابي»، فيظهر بدلاً منه «عضو».
يُنصح بذكر هذه الصفحة في الشروط والأحكام.

## دمج سحوبات المنصة السابقة
لعرض سحوبات نُفّذت فعلاً لأعضائك على منصة أخرى. تظهر في صفحة السحوبات بشارة «عبر [EXTERNAL_SOURCE_NAME]».

**سحوبات سابقة (دفعة واحدة):** املأ `templates/external_payouts.csv` ثم أرسله للبوت كملف مع التعليق `/import_payouts`.
الأعمدة: `name,amount,method,paid_at,receipt` — الطريقة `zaincash` أو `qicard` أو `bank`، والتاريخ بتوقيت بغداد `2026-10-05 14:30`.
يرد البوت بعدد المستورد وأسباب رفض أي سطر.

**القائمة اليومية:** في نهاية كل يوم (أو بعد كل دفعة تحويلات) املأ `templates/daily_payouts.csv` بسحوبات اليوم المنفّذة،
ويكفي كتابة الوقت فقط في عمود `paid_at` (مثل `14:30`) ويُعتبر تاريخ اليوم تلقائياً. أرسل الملف للبوت في المحادثة الخاصة
مع التعليق `/import_payouts`. تظهر السحوبات فوراً في صفحة «سحوبات الأعضاء» بأوقاتها الحقيقية، وتُنشر في قناة السحوبات إن وُجدت.
الأوقات التي لم تأتِ بعد تُرفض؛ أضفها في قائمة لاحقة بعد تنفيذها.

**قناة السحوبات (اختياري):** أنشئ قناة، أضف البوت مشرفاً فيها، وضع معرّفها في `PAYOUTS_CHANNEL_ID`.
يُنشر فيها كل سحب منفّذ داخل البوت، وكل قائمة مستوردة كرسالة واحدة مرتبة زمنياً مع العدد والمجموع.

**سحب يُنفَّذ الآن على المنصة الأخرى:** `/extpayout الاسم | المبلغ | zaincash | رقم_الإيصال` (يُسجَّل بوقت التنفيذ الحالي).

القيود: لا تواريخ مستقبلية، رقم إيصال فريد لكل سحب، لا يمكن تعديل السجل بعد الإدخال، وكل استيراد مسجّل في سجل التدقيق باسم المشرف.
احتفظ بإيصالات التحويل الأصلية؛ فهي ما يثبت صحة هذه السجلات عند أي مراجعة.

```
/stats
/addtask العنوان | الجهة | المكافأة | المقاعد | الساعات | الوصف | المتطلبات | الإثبات
/addproject الاسم | النوع | القطاع | رأس المال | الأيام | المخاطر | طريقة الاحتساب | الوصف | نموذج العمل | المخاطر التفصيلية
/pstatus <رقم_المشروع> study|open|active|closed
/settle <رقم_المشروع> <النسبة>      مثال: /settle 3 4.5  أو  /settle 3 -2

/freeze <معرّف_المستخدم>   /unfreeze <معرّف_المستخدم>
/extpayout الاسم | المبلغ | الطريقة | رقم_الإيصال
(ملف CSV مع التعليق) /import_payouts
```

## قبل الإطلاق
- الحصول على الترخيص اللازم لتلقي الأموال وإدارة الاستثمارات (البنك المركزي العراقي / هيئة الأوراق المالية حسب النشاط)، ووضع بياناته في `LICENSE_TEXT`.
- عقود موقّعة مع جهات العمل الحقيقية التي تموّل المهام.
- نسخ احتياطي يومي لملف `data/thiqa.db` ومجلد `data/uploads`.
- الخطوة التالية المقترحة: لوحة إدارة ويب مستقلة (جداول المستخدمين، التقارير، تصدير CSV/PDF، صلاحيات متعددة)، والانتقال إلى PostgreSQL عند نمو عدد المستخدمين.
